--------------------------------------------------------------------------------
1. HOW TO RUN
--------------------------------------------------------------------------------

  Everything:
      bash test/run-all-tests.sh

  One layer at a time:
      javac --release 17 -d build/classes $(find src -name "*.java")
      javac --release 17 -d build/test -cp build/classes test/*.java

  The --release 17 matters: compiling with a newer JDK than the one that runs
  the classes gives UnsupportedClassVersionError. run-all-tests.sh passes it
  for you.

      java -cp "build/classes;build/test" UnitTests
      java -cp "build/classes;build/test" IntegrationTests
      bash test/run-system-tests.sh

  Every layer exits non-zero if anything fails, so run-all-tests.sh can be
  trusted as a single yes/no answer.

3. WHAT EACH LAYER COVERS
--------------------------------------------------------------------------------

UNIT TESTS - test/UnitTests.java
  The ADTs and each module's core logic in isolation.

    1.1  List ADT          add, insert, remove, replace, getEntry, contains,
                           getPosition, removeEntry, clear, out-of-range
                           access, growth past the initial capacity
    1.2  Added operations  filter, search, countIf, sort - including that a
                           filtered copy is independent of its source
    1.3  Merge stability   equal entries keep their original relative order
    1.4  Stack ADT         push, pop, peek, empty-stack behaviour, growth
    1.5  Queue ADT         enqueue, dequeue, getFront, the circular wrap,
                           growth while holding entries
    1.6  BST               insert, duplicate rejection, search hit and miss,
                           in-order traversal, the degenerate sorted-input tree

    2.x  Module 1          guest ID generation, urgent insertion policy,
                           registration sequence, undo stack, name and contact
                           validation
    3.x  Module 2          append-only log, rollback stack, collapsing the log
                           to current state per room, sorting, searching,
                           duplicate-status rejection
    4.x  Module 3          BST lookup, dual List+BST storage, billing balances,
                           entity equals, room-availability date overlap
    5.x  Module 4          FIFO redemption queue, points and tier progression,
                           redemption affordability, sorting tie-breakers,
                           expiring points

  LIMITATION - state this if anyone asks. Where a rule lives in a private
  method or behind a console prompt, the rule is reproduced in the test file
  rather than called. If the original changes and the copy does not, the test
  keeps passing against the old rule. Those copies are marked in the source.

INTEGRATION TESTS - test/IntegrationTests.java
  Real DAOs, initializers and ADTs working together. Nothing is a copy here.

    1  Seeding        every initializer produces usable data; seeded arrivals
                      are all in the past and all on today; guest IDs unique
    2  Persistence    save then reload returns equivalent data for walk-ins,
                      housekeeping tasks and bookings; a status change
                      survives; a missing file falls back to seeding
    3  Cross-ADT      the same bookings held in a List and a BST stay
                      consistent, hold references not copies, and traverse in
                      sorted order
    4  Shared ADT     one generic List implementation serves four entity types
                      without interference; filter and sort never mutate their
                      source; countIf and filter always agree
    5  Shared UI      MessageUI's framed-box helpers and the rewritten banner
                      handle every letter, spaces, hyphens, empty input,
                      oversized input and undefined characters

SYSTEM TESTS - test/run-system-tests.sh
  The whole application driven through its real console menus. This is the
  only layer that exercises the boundary classes, menu loops and clear-screen
  behaviour.

     1  Navigation in and out of all four modules
     2  Invalid menu input - letters, out-of-range, negatives, decimals, empty
     3  Module 1 cancel at the very first input
     4  Module 1 validation, every branch
     5  Module 1 undo: peek, decline, then confirm
     6  Module 1 serve and cancel both confirm, and declining changes nothing
     7  Module 1 pagination, and that [Q] returns to the menu in one keystroke
        while a single-page listing still pauses
     8  Module 1 search, filter and all four sort orders
     9  Module 1 both reports
    10  Module 2 menu and task log
    11  Module 3 menu, search, confirmation-number validation
    12  Module 4 menu, members, rewards, empty redemption queue
    13  A full sweep of every module in one session
    14  Data registered in one run is still there in the next

  Runs in build/systest so the project's .dat files are never touched.

4. THE TESTS WERE THEMSELVES TESTED
--------------------------------------------------------------------------------

A test that cannot fail is worthless, so two deliberate defects were injected
into the source and the suite was re-run:

  MUTATION 1 - merge sort stability
      Changed the merge comparison in ArrayList.sort() from <= 0 to < 0, so
      ties take from the right half instead of the left.
      RESULT: 5 unit tests failed, all of them stability checks.

  MUTATION 2 - the serve confirmation
      Replaced the Y/N check in serveNextGuest() with if (false), so serving
      proceeds regardless of the answer.
      RESULT: 3 system tests failed - "serving asks for confirmation",
      "declining leaves the guest waiting", "declining does not serve anyone".

Both mutations were reverted and the source verified against the last commit
with git diff before continuing.


--------------------------------------------------------------------------------
5. DEFECTS THE TESTING FOUND
--------------------------------------------------------------------------------

  Found in Module 1 during development, all fixed:
    1  Quitting a paged listing took two keystrokes and left the table on
       screen.
    2  "Serve next guest" changed state with no confirmation, unlike cancel
       and undo.
    3  Cancelling a status or type filter returned silently.
    4  Validation used regex; replaced with hand-written character checks.

  Found across the shared code during the compliance audit, all fixed:
    5  MessageUI held the banner font in a java.util.HashMap - a banned class,
       hidden because it was fully qualified rather than imported.
    6  Three control classes wrote to the console directly, breaking ECB.
    7  BillingRecord and FrontDeskRecord had no equals/hashCode/toString, so
       the List ADT could not match a record reloaded from file.
    8  RewardInitializer had no @author.

  Two apparent failures were investigated and found to be errors in the test
  script, not the application: Module 1's title is letter-spaced on screen, and
  the pager prompt is followed by the scroll-based clear rather than a pause.
  Both assertions were corrected.
